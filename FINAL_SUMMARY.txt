PHASE 1: DEVELOPMENT (Week 1-2)
─────────────────────────────────

1. Install: pip install -r requirements.txt

2. Run testing:
   python development/dev_testing.py

3. Choose SCENARIO 1: Test different models
   - Loads Llama 2 7B, 13B, Mistral, etc.
   - Tests same question with each
   - You rate quality (1-5)
   - System shows: quality, speed, consistency
   - Saves metrics to metrics/model_comparison.json

4. Choose SCENARIO 2: Test different prompts
   - Tests v1.0 (basic), v1.1 (improved), v2.0 (professional)
   - Tests same model with each prompt
   - You rate each prompt
   - System shows which prompt is best
   - Saves metrics to metrics/prompt_comparison.json

5. Choose SCENARIO 3: End-to-end test
   - Full system test with your chosen setup
   - Chat + Report + 3D generation
   - Verifies everything works together

6. Make decision:
   - Best Model: _______________  (e.g., Llama 2 13B)
   - Best Prompt: _______________  (e.g., v2.0)
   - Quality Rating: _______________  (e.g., 5/5)


PHASE 2: PREPARE PRODUCTION (Day 3)
────────────────────────────────────

1. Update config/production.py:
   MODEL_NAME = "meta-llama/Llama-2-13b-hf"  # Your choice
   LLM_PROVIDER = "unsloth"
   DATABASE_URL = "postgresql://..."  # Your prod DB
   TEMPERATURE = 0.5  # More consistent

2. Lock your prompts:
   Copy best prompt version to instructions/
   Mark as "v2.0-locked"

3. Verification checklist:
   ☑ Model testing complete
   ☑ Prompt testing complete
   ☑ Metrics reviewed
   ☑ Quality ≥ 4/5
   ☑ Response time < 10s
   ☑ No errors in logs
   ☑ Unit tests pass


PHASE 3: DEPLOY TO PRODUCTION (Day 4)
──────────────────────────────────────

1. Start production server:
   ENVIRONMENT=production python -m uvicorn app:app --host 0.0.0.0 --port 8000

2. Verify it's running:
   curl http://localhost:8000/api/health
   # Should return: {"status": "healthy", ...}

3. Test with real request:
   curl -X POST http://localhost:8000/api/chat \
     -H "Content-Type: application/json" \
     -d '{"question": "How do I design a cube?"}'

4. Check logs:
   tail -f logs/app.log

5. It's LIVE! ✓
   Users can now access:
   http://your-server.com/api/chat


PHASE 4: ONGOING MONITORING (Daily/Weekly)
──────────────────────────────────────────

Daily:
- Check logs: tail -f logs/app.log
- Look for errors or degradation
- Response times staying low?

Weekly:
- Review user feedback
- Count questions asked
- Rate user satisfaction
- Track response times

Monthly:
- Full metrics analysis
- User satisfaction scores
- Decision: improve or keep?

If issues:
- Go back to DEVELOPMENT
- Test new models/prompts
- Deploy improved version
